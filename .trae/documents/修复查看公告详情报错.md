# 修复查看公告详情报错 - 实施计划

## Bug 根因

**`markNoticeRead` API 将 `noticeId` 作为 URL 查询参数发送，但后端从 POST body 读取。**

### 调用链追踪

1. 用户点击查看公告详情 → 调用 `markNoticeRead(noticeId)`
2. APP 端 `api/system/notice.js` 第 16 行：
   ```js
   export function markNoticeRead(noticeId) {
     return request({ url: '/system/notice/markRead', method: 'post', params: { noticeId } })
   }
   ```
3. `request.js` 第 40-44 行将 `params` 序列化为 URL 查询参数：
   ```js
   if (options.params) {
     let url = options.url + '?' + tansParams(options.params)
     options.url = url
   }
   ```
4. 实际请求变成：`POST /system/notice/markRead?noticeId=5`（body 为空）
5. 后端 `SysNoticeController.php` 第 75 行：
   ```php
   $noticeId = $request->post('noticeId');
   ```
   `$request->post()` 从 POST body 读取，不是查询参数 → 得到 `null`
6. `markRead($userId, null)` → `SysNoticeRead::create(['notice_id' => null])` → 数据库错误 → 500 响应
7. APP `request.js` 对 500 响应弹出 toast，`errorCode[500]` 未定义，回退到 `errorCode['default']` = **"系统未知错误，请反馈给管理员"**

### Web 前端同样的问题

`front/src/api/system/notice.js` 第 60-65 行：
```js
export function markNoticeRead(noticeId) {
  return request({ url: '/system/notice/markRead', method: 'post', params: { noticeId } })
}
```
Axios 的 `params` 也是 URL 查询参数，不是 POST body，同样导致后端收到 `null`。

---

## 修复步骤

### 步骤 1：APP 端 - `markNoticeRead` 改用 `data` 发送 POST body

**文件**: `AppV3/src/api/system/notice.js`

```js
// 修改前
export function markNoticeRead(noticeId) {
  return request({ url: '/system/notice/markRead', method: 'post', params: { noticeId } })
}

// 修改后
export function markNoticeRead(noticeId) {
  return request({ url: '/system/notice/markRead', method: 'post', data: { noticeId } })
}
```

### 步骤 2：Web 前端 - `markNoticeRead` 改用 `data` 发送 POST body

**文件**: `front/src/api/system/notice.js`

```js
// 修改前
export function markNoticeRead(noticeId) {
  return request({ url: '/system/notice/markRead', method: 'post', params: { noticeId } })
}

// 修改后
export function markNoticeRead(noticeId) {
  return request({ url: '/system/notice/markRead', method: 'post', data: { noticeId } })
}
```

### 步骤 3：后端 - `markRead` 兼容查询参数和 POST body（防御性编程）

**文件**: `webman/app/controller/system/SysNoticeController.php`

```php
// 修改前
$noticeId = $request->post('noticeId');

// 修改后：优先从 POST body 取，取不到则从查询参数取
$noticeId = $request->post('noticeId') ?? $request->input('noticeId');
```
