# 数据概览全显示0 - 深度排查与修复计划

## 问题现象
首页"最近订单"有数据，但"数据概览"中成交客数、成交金额、操作客数全部显示0。

## 之前的修复（已生效但仍为0）

1. ✅ `getUserDataScope()` — 兼容数组/对象两种角色格式
2. ✅ `getCustomDeptIds()` — 同上
3. ✅ `isAdmin()` — 严格比较改宽松比较
4. ✅ 筛选条件从 `order_status='1'` 改为 `enterprise_audit_status='1'`

## 真正的根因（3层叠加）

### 根因1：筛选条件变更后仍然匹配不到数据

从备份数据分析，8条订单的实际状态：

| order_id | order_status | enterprise_audit_status | 类型 |
|----------|-------------|------------------------|------|
| 1,2,3,5,8 | '1'(已成交) | **'0'(未审核)** | 正常销售订单 |
| 7,9,10 | '3'(已完成) | '1'(已审核) | 还款订单 |

- 用 `order_status='1'` → 只能匹配5条销售订单，但它们 `enterprise_audit_status='0'`
- 用 `enterprise_audit_status='1'` → 只能匹配3条还款订单，但它们 `order_status='3'`

**关键问题**：5条正常销售订单都没有企业审核（`enterprise_audit_status='0'`），所以无论用哪个条件，统计结果都不完整。

### 根因2：`today` 日期过滤导致当天无数据

代码使用 `whereDate('create_time', $today)` 过滤今日数据。备份数据的 `create_time` 范围是 2026-05-09 到 2026-05-12，如果今天不是这些日期，**今日统计必然为0**。

月度统计虽然用 `where('create_time', '>=', $monthStart)` 过滤本月，但如果当前月份与数据月份不同，月度也为0。

### 根因3：数据权限逻辑可能仍限制了非管理员用户

即使用户是管理员（userId=1），`isAdmin()` 返回 true，`getVisibleUserIds()` 会返回所有用户ID。但如果用户不是管理员，且 `getUserDataScope()` 仍返回 '5'（仅本人），则只能查自己的数据。

**但所有数据的 `creator_user_id=1`**，如果当前登录用户不是 userId=1，就查不到任何数据。

## 修复方案

### 核心思路：统计应基于"已确认"的订单，不区分订单类型

用户明确要求"只要企业确认了这个订单就可以统计"，所以筛选条件应该是 `enterprise_audit_status='1'`，但还需要**同时包含正常销售订单**（order_status='1'）。

**问题**：正常销售订单的 `enterprise_audit_status` 目前全是 '0'（未审核），所以它们不会被统计。

**解决方案**：统计条件改为：`order_status IN ('1', '3')`（已成交 + 已完成），不再依赖 `enterprise_audit_status`。因为用户说"最近订单有数据"，这些订单在列表中可见，说明它们在业务上已经是有效的。

### 步骤1：修改 HomeStatsService 筛选条件

将成交客数和成交金额的筛选条件从 `enterprise_audit_status='1'` 改为 `order_status IN ('1', '3')`：

```php
// 成交客数 - 已成交(1)或已完成(3)的订单
BizSalesOrder::whereIn('order_status', ['1', '3'])
    ->whereIn('creator_user_id', $userIds)
    ->whereDate('create_time', $today)
    ->distinct()->count('customer_id');
```

这样5条已成交订单 + 3条已完成订单都会被统计。

### 步骤2：增加调试日志，排查数据权限和日期过滤问题

在 `getTodayStats()` 中添加临时日志，输出：
- 当前登录用户ID和isAdmin状态
- getVisibleUserIds() 返回的用户ID列表
- today和monthStart的值
- 各查询的原始SQL和结果

这样可以在服务端日志中看到具体哪个环节导致0值。

### 步骤3：修复前端数据解析（防御性）

检查 `statsRes.data` 的结构是否与前端解析逻辑匹配。后端返回：
```json
{
  "code": 200,
  "data": {
    "dealCustomerCount": {"today": 0, "month": 5},
    "dealAmount": {"today": 0, "month": 17077},
    "operationCustomerCount": {"today": 0, "month": 1}
  }
}
```

前端 `request.js` 中 `resolve(res.data)` 返回的是外层响应体，所以 `statsRes` 已经是 `{code: 200, data: {...}}`，`statsRes.data` 是内层data。需要确认这个解析链路是否正确。
