# 数据完整性检查与修复计划

## 问题总览

通过对比数据库表结构（`fuchen.sql`）和应用代码中的数据写入逻辑，发现以下数据完整性问题，按严重程度排序。

---

## 严重级别1：数据写入错误（字段不存在/数据丢失）

### 1.1 `biz_order_item` 操作订单明细写入不存在的字段 `subtotal`

**文件**：[BizOperationRecordService.php:244-253](file:///f:/fuchen/webman/app/service/BizOperationRecordService.php#L244-L253)

```php
BizOrderItem::create([
    'order_id' => $order->order_id,
    'product_name' => $record->product_name,
    'quantity' => intval($record->operation_quantity ?? 1),
    'unit_price' => floatval($record->consume_amount ?? 0) / max(intval($record->operation_quantity ?? 1), 1),
    'subtotal' => floatval($record->consume_amount ?? 0),  // BUG: 表中无此字段！
    'create_time' => date('Y-m-d H:i:s')
]);
```

**问题**：`biz_order_item` 表中**没有 `subtotal` 字段**，数据被静默丢弃。同时缺少 `deal_amount`、`paid_amount`、`owed_amount` 三个重要金额字段。

**修复**：移除 `subtotal`，补充 `deal_amount`、`paid_amount`、`owed_amount`。

### 1.2 `biz_order_item` 还款订单明细缺少 `unit_price` 和 `owed_amount`

**文件**：[BizRepaymentService.php:151-160](file:///f:/fuchen/webman/app/service/BizRepaymentService.php#L151-L160)

```php
BizOrderItem::create([
    'order_id' => $order->order_id,
    'product_name' => '还款-' . ($data['package_name'] ?? '欠款'),
    'quantity' => 1,
    'deal_amount' => $repaymentAmount,
    'paid_amount' => $repaymentAmount,
    // 缺少 unit_price 和 owed_amount
    'customer_feedback' => '',
    'remark' => '支付方式: ' . ($data['payment_method'] ?? '-'),
    'create_time' => date('Y-m-d H:i:s')
]);
```

**修复**：补充 `unit_price => $repaymentAmount` 和 `owed_amount => 0`。

## 严重级别2：关联名称字段未保存

### 2.1 `biz_customer_package` 缺少 `enterprise_name` 和 `store_name`

**文件**：[BizSalesOrderService.php:207-223](file:///f:/fuchen/webman/app/service/BizSalesOrderService.php#L207-L223)

```php
$package = BizCustomerPackage::create([
    'package_no' => $packageNo,
    'customer_id' => $order->customer_id,
    'customer_name' => $order->customer_name,
    'order_id' => $order->order_id,
    'order_no' => $order->order_no,
    'enterprise_id' => $order->enterprise_id,
    'store_id' => $order->store_id,
    // 缺少 enterprise_name 和 store_name！
    'package_name' => $packageName,
    ...
]);
```

**问题**：只保存了 `enterprise_id` 和 `store_id`，没有保存对应的 `enterprise_name` 和 `store_name`。后续操作记录通过套餐反查企业/门店名称时查不到，导致操作记录和档案中企业/门店名称为空。

**修复**：从 `$order` 中补充 `enterprise_name` 和 `store_name`。

### 2.2 `biz_operation_record` 的 `enterprise_id`/`store_id`/`enterprise_name`/`store_name` 经常为空

**文件**：[BizOperationRecordService.php:43-91](file:///f:/fuchen/webman/app/service/BizOperationRecordService.php#L43-L91)

**问题**：
- 持卡操作时，代码尝试从 `packageItem → package → order` 反查企业/门店名称（第74-81行），但如果 `biz_customer_package` 本身就没有 `enterprise_name`/`store_name`（问题2.1），反查链路断裂
- 体验操作时（第84-89行），`package_id` 被强制设为 null，完全没有反查逻辑
- 控制器（[BizOperationRecordController.php:29-41](file:///f:/fuchen/webman/app/controller/business/BizOperationRecordController.php#L29-L41)）没有自动填充 `enterprise_id`/`store_id`/`enterprise_name`/`store_name`

**修复**：在 `insertRecord()` 中，当 `enterprise_id`/`store_id` 为空时，从客户信息自动回填。

### 2.3 `biz_package_item` 缺少 `plan_price`（方案总价）

**文件**：[BizSalesOrderService.php:231-242](file:///f:/fuchen/webman/app/service/BizSalesOrderService.php#L231-L242)

```php
BizPackageItem::create([
    'package_id' => $package->package_id,
    'product_name' => $item['product_name'],
    'unit_price' => $unitPrice,
    'deal_price' => $dealPrice,
    // 缺少 plan_price！
    'paid_amount' => $itemPaidAmount,
    'owed_amount' => $itemOwedAmount,
    ...
]);
```

**问题**：`plan_price`（方案总价）始终为默认值 0.00，丢失了原始方案定价信息。

**修复**：从前端传入的 items 数据中提取 `plan_price`，若无则默认等于 `deal_price`。

## 严重级别3：操作订单状态和审核状态不合理

### 3.1 操作订单 `order_status='1'` 但 `enterprise_audit_status='1'`，跳过了待确认环节

**文件**：[BizOperationRecordService.php:220-242](file:///f:/fuchen/webman/app/service/BizOperationRecordService.php#L220-L242)

```php
$order = BizSalesOrder::create([
    ...
    'order_status' => '1',           // 直接设为"已成交"
    'enterprise_audit_status' => '1', // 直接设为"企业已确认"
    'finance_audit_status' => '1',    // 直接设为"财务已确认"
    ...
]);
```

**问题**：操作订单直接跳过审核流程，`order_status` 设为 '1'（已成交），`enterprise_audit_status` 设为 '1'（企业已确认）。这与用户之前的需求"只要企业确认了这个订单就可以统计"一致，所以 `enterprise_audit_status='1'` 是合理的。但 `order_status='1'` 需要确认是否正确——操作订单是否应该有"待确认"状态？

**结论**：保持现状，操作订单自动确认是合理的业务逻辑。

## 严重级别4：审计字段默认值不一致

### 4.1 四张表的审计字段 `DEFAULT NULL` 缺少自动时间戳

| 表 | create_time | update_time |
|------|-----------|-----------|
| `biz_attendance_config` | NULL | NULL |
| `biz_plan` | NULL | NULL |
| `biz_shipment` | NULL | NULL |
| `biz_repayment_record` | NULL | NULL |

其他25张表的审计字段都有 `DEFAULT CURRENT_TIMESTAMP`，这4张表不一致。

**修复**：通过 ALTER TABLE 统一默认值，同时在应用代码中也确保手动设置。
