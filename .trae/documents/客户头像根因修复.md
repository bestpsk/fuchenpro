# 客户头像不显示 + 点击无反应 - 真正的根因修复

## 根因分析

### 问题1：创建/修改顾客后头像不显示

**真正的根因**：`u-avatar` 组件的渲染逻辑是 `v-else-if="text"` 优先于 `v-else`（图片），**`text` 的优先级高于 `src`**！

```html
<!-- u-avatar 内部源码 -->
<up-icon v-if="icon" ... />        <!-- 优先级1：图标 -->
<up-text v-else-if="text" ... />   <!-- 优先级2：文字 ← 高于图片！ -->
<image v-else :src="avatarUrl" />  <!-- 优先级3：图片 ← 最低！ -->
```

当同时传入 `text` 和 `src` 时，**永远显示文字**，图片根本不会被渲染。

之前的修复把 `text` 改为始终设置首字母，结果反而让图片永远无法显示！

### 问题2：编辑页面点击头像无反应

`u-avatar` 组件内部有 `@tap="clickHandler"` 拦截了点击事件，但没有冒泡到外部的 `avatar-section` 的 `@click`。在 uni-app 中，`@tap` 和 `@click` 的事件冒泡机制可能导致外部点击处理器收不到事件。

## 修复方案

### 步骤1：修复 `u-avatar` 的 text/src 互斥逻辑

**核心思路**：当有头像URL时，不传 `text`（让图片显示）；当没有头像URL时，传 `text`（显示首字母）。

```html
<!-- 客户列表 -->
<u-avatar 
  :src="getAvatarUrl(item.avatar)" 
  :text="item.avatar ? '' : (item.customerName ? item.customerName.charAt(0) : '')" 
  ...
/>
```

但这样图片加载失败时不会回退到文字。需要用另一种方式：**监听图片加载失败事件，动态切换为文字模式**。

更简单的方案：**不使用 `u-avatar` 的 `text` 属性，改用条件渲染**：

```html
<!-- 有头像URL时显示图片头像，否则显示文字头像 -->
<u-avatar v-if="item.avatar" :src="getAvatarUrl(item.avatar)" size="40" mode="aspectFill" />
<u-avatar v-else :text="item.customerName ? item.customerName.charAt(0) : ''" size="40" :bg-color="..." color="#fff" />
```

但这样图片加载失败时会显示默认灰色头像。更好的方案是**使用 `@error` 事件回退**：

```html
<u-avatar 
  v-if="item.avatar && !avatarErrorMap[item.customerId]"
  :src="getAvatarUrl(item.avatar)" 
  size="40" 
  @error="onAvatarError(item.customerId)"
/>
<u-avatar 
  v-else 
  :text="item.customerName ? item.customerName.charAt(0) : ''" 
  size="40" 
  :bg-color="item.gender === '1' ? '#FF6B9D' : '#3D6DF7'" 
  color="#fff" 
/>
```

但这样太复杂了。**最简洁的方案**：用条件渲染，图片加载失败时 `u-avatar` 内部的 `errorHandler` 会自动显示内置默认头像，这已经足够好了。

### 步骤2：修复编辑页面点击头像无反应

将 `@click` 从外层 `avatar-section` 移到 `u-avatar` 上，或者使用 `@click.stop` 阻止内部事件拦截：

```html
<view class="avatar-section">
  <view @click="chooseAvatar">
    <u-avatar ... />
  </view>
  ...
</view>
```

或者更简单：给 `u-avatar` 添加 `@click` 事件：

```html
<u-avatar ... @click="chooseAvatar" />
```
