# 轮播图裁剪上传失败修复

## 问题分析

错误提示："上传文件异常，上传失败"

**根因**：`request.js` 的请求拦截器中，POST 请求会进行**防重复提交检查**，将 `config.data` 用 `JSON.stringify()` 序列化后存入 sessionStorage 进行比对。但 `FormData` 对象调用 `JSON.stringify()` 会返回 `"{}"`（空对象字符串），导致：

1. 第一次上传请求：`sessionStorage` 存入 `{ url: '/common/upload', data: '{}', time: xxx }`
2. 后端处理上传 → 返回结果
3. 但实际上 `FormData` 无法被正确序列化，防重复提交逻辑可能干扰了请求

**更关键的问题**：`confirmCrop()` 中使用 `request()` (axios) 发送 FormData 上传请求时，axios 默认的 `Content-Type` 是 `application/json;charset=utf-8`（见 request.js 第22行），而 FormData 上传需要 `Content-Type: multipart/form-data`。虽然 axios 在检测到 FormData 时会自动设置正确的 Content-Type，但 request.js 中 `axios.defaults.headers['Content-Type']` 的全局默认值可能覆盖了这个自动行为。

**另外**：后端返回 `{ code: 500, msg: "上传文件异常" }` 说明 `$request->file('file')` 返回了 null 或无效文件，即后端没有正确接收到上传的文件。

**最可能的原因**：axios 全局默认 `Content-Type: application/json` 导致 FormData 没有以 `multipart/form-data` 格式发送，后端无法解析文件字段。

## 修复方案

在 `confirmCrop()` 中上传时，显式设置 `Content-Type: multipart/form-data`，让浏览器自动设置正确的 boundary。

同时跳过防重复提交检查（设置 `repeatSubmit: false`）。

## 修改文件

`front/src/views/system/banner/index.vue`

## 实施步骤

### 步骤1：修改 confirmCrop 中的上传请求

```javascript
const res = await request({
  url: '/common/upload',
  method: 'post',
  data: formData,
  headers: {
    'Content-Type': 'multipart/form-data',
    'repeatSubmit': false
  }
})
```

- `'Content-Type': 'multipart/form-data'` — 让浏览器自动设置带 boundary 的正确 Content-Type
- `'repeatSubmit': false` — 跳过防重复提交检查（FormData 无法正确序列化）
