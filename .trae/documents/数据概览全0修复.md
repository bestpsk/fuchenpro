# 数据概览全显示0 - 修复计划

## 问题现象
首页"最近订单"有数据，但"数据概览"中成交客数、成交金额、操作客数全部显示0。

## 根因分析

经过深入排查，发现以下**3个关键问题**导致统计全为0：

### 问题1（核心Bug）：`getUserDataScope()` 中 roles 数组访问方式错误

**文件**：[HomeStatsService.php:94-104](file:///f:/fuchen/webman/app/service/HomeStatsService.php#L94-104)

`LoginUser` 从 Redis 反序列化后，`$loginUser->user->roles` 是一个**普通关联数组**（JSON反序列化结果），而非 `SysRole` 模型对象集合。代码中使用 `$role->data_scope`（对象属性访问语法）访问数组元素，在 PHP 8.x 中会触发 Warning 并返回 null，导致 `isset($role->data_scope)` 始终为 false。

**结果**：`getUserDataScope()` 始终返回默认值 `'5'`（仅本人），无论用户实际数据权限是什么。

**同样的问题也存在于** `getCustomDeptIds()` 方法中的 `$role->role_id` 访问。

### 问题2：非管理员用户的数据权限被错误限制为"仅本人"

由于问题1，所有非管理员用户的数据权限都被降级为"仅本人"（data_scope='5'），`getVisibleUserIds()` 只返回当前用户ID。

而数据库中所有订单的 `creator_user_id = 1`（admin创建），如果当前登录用户不是 admin，查询 `whereIn('creator_user_id', [$userId])` 匹配不到任何订单，统计自然为0。

### 问题3：统计筛选条件与业务需求不一致

用户明确要求"只要企业确认了这个订单就可以统计"，但当前代码按 `order_status = '1'`（已成交）过滤。从备份数据看，`order_status='3'` 的还款订单也有 `enterprise_audit_status='1'`（企业已确认），这些订单应纳入统计但被排除了。

## 修复方案

### 步骤1：修复 `getUserDataScope()` - 兼容数组和对象两种角色数据格式

```php
private static function getUserDataScope($loginUser)
{
    $roles = $loginUser->user->roles ?? [];
    $minScope = '5';
    foreach ($roles as $role) {
        // 兼容数组（Redis反序列化）和对象（Eloquent模型）两种格式
        $dataScope = is_array($role) ? ($role['data_scope'] ?? '5') : ($role->data_scope ?? '5');
        if ($dataScope < $minScope) {
            $minScope = $dataScope;
        }
    }
    return $minScope;
}
```

### 步骤2：修复 `getCustomDeptIds()` - 同样兼容数组和对象

```php
private static function getCustomDeptIds($loginUser)
{
    $roles = $loginUser->user->roles ?? [];
    $roleIds = [];
    foreach ($roles as $role) {
        $roleId = is_array($role) ? ($role['role_id'] ?? null) : ($role->role_id ?? null);
        if ($roleId !== null) {
            $roleIds[] = $roleId;
        }
    }
    if (empty($roleIds)) return [];
    return SysRoleDept::whereIn('role_id', $roleIds)->pluck('dept_id')->toArray();
}
```

### 步骤3：修复 `isAdmin()` 严格比较问题

**文件**：[LoginUser.php:39-41](file:///f:/fuchen/webman/app/common/LoginUser.php#L39-41)

将 `$this->userId === 1` 改为 `$this->userId == 1`，防止 JSON 反序列化后类型不一致导致判断失败。

```php
public function isAdmin()
{
    return $this->userId == 1 || ($this->user && method_exists($this->user, 'isAdmin') && $this->user->isAdmin());
}
```

同样修复 `SysUser::isAdmin()`：
```php
public function isAdmin()
{
    return $this->user_id == 1;
}
```

### 步骤4：修改统计筛选条件 - 按企业确认状态过滤

将 `order_status = '1'` 改为 `enterprise_audit_status = '1'`（企业已确认），符合用户"只要企业确认了就可以统计"的需求。

```php
// 修改前
BizSalesOrder::where('order_status', '1')

// 修改后
BizSalesOrder::where('enterprise_audit_status', '1')
```

### 步骤5：增加防御性处理 - 确保 userIds 不为空

在 `getVisibleUserIds()` 中，当查询结果为空时回退到当前用户ID，避免 `whereIn` 传入空数组导致SQL异常。
